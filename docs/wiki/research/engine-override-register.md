## CfgMagazines >> <magazine> >> initSpeed

- Verdict: **ADOPT** (implemented)
- Source: data/ballistics/loads.json: service_velocity_ms (grade documented, US military specifications and TM 43-0001-27) with the manufacturer velocity table as the fallback (grade claimed, Hornady and Lapua).
- Reason: initSpeed is a plain scalar. The real cartridge muzzle velocity moves the engine's own projectile from the muzzle.
- Ceiling: Load-time and global. The PBO is the only off switch.

## CfgMagazines >> <magazine> >> tracersEvery

- Verdict: **RECONCILE** (withheld)
- Source: None held. The corpus holds tracer rounds as projectiles and loads but no per-magazine tracer ratio.
- Reason: The real 4:1 ball-to-tracer ratio is a LINKED-BELT property. A magazine is either all ball or all tracer, so the ratio does not map to a magazine scalar without inventing a figure. The vanilla config already sets tracersEvery to 0, 1, 4 or 5 per magazine.
- Ceiling: No committed source for a per-magazine ratio. A belt ratio is a modelling choice, not a measured magazine property.

## CfgAmmo >> <ammo> >> airFriction

- Verdict: **ADOPT** (implemented)
- Source: Derived from the held ballistic coefficient and standard drag curve: data/ballistics/projectiles.json (bc_g1 or bc_g7, measured or documented) and data/ballistics/sources/drag_functions.json (JBM and McCoy).
- Reason: The engine applies quadratic drag a = airFriction * v^2. The verified AEE drag model states the same form with 0.00068418 * (Cd / BC) * v^2, so the coefficient is derivable at the reference muzzle Mach. No engine number is copied.
- Ceiling: Load-time and global. One constant cannot follow the Mach-dependent drag over the whole flight; the value is calibrated at the muzzle Mach, where the vanilla values also sit.

## CfgWeapons >> <weapon> >> dispersion

- Verdict: **RECONCILE** (withheld)
- Source: None held. The weapon corpus holds mass and twist, not measured group size.
- Reason: dispersion is a cone of fire in the engine, not a measured group size, so a real Minuteman-of-angle cannot be mapped without inventing the conversion. No committed accuracy corpus exists.
- Ceiling: Engine cone, not a group-size solver. A corpus of measured dispersion must land first.

## CfgWeapons >> <weapon> >> maxZeroing / discreteDistance[]

- Verdict: **RECONCILE** (withheld)
- Source: None held. No committed sight-adjustment corpus.
- Reason: The real sight elevation range is a property of the sight, which is a separate optic class. No committed source holds the adjustment range per sight.
- Ceiling: Per-scope, and no corpus. The runtime zeroing kernel owns the trajectory correction.

## CfgWeapons >> <weapon> >> recoil (a CfgRecoils curve)

- Verdict: **RECONCILE** (withheld)
- Source: The recoil corpus holds free recoil energy (weapons.json mass, loads.json muzzle velocity and charge, SAAMI formulae).
- Reason: The CfgRecoils array is a fixed-shape camera-offset curve, not a physical impulse. Deriving the camera offsets from the impulse needs the engine's hidden mapping. AEE computes the richer physical recoil at run time (fnc_calculateRecoil.sqf).
- Ceiling: The engine curve shape is engine-internal. The runtime kernel is richer.

## CfgVehicles >> <vehicle> >> armor / HitPoints >> armor

- Verdict: **RECONCILE** (withheld)
- Source: STANAG 4569 protection levels L1 to L6 (docs/wiki/research/vehicle-armour-research.md).
- Reason: armor is a health pool, not a ballistic gate: the formula (HIT*HIT)/Armor depletes with hits and is independent of the bisurf penetration gate. AEE resolves protection dynamically by design (fnc_getVehicleArmour). A static override would double-own the outcome.
- Ceiling: Health pool, not penetration. The runtime kernel is the authority.
