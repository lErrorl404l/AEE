# ADR-013: Wildlife Ambience Ownership and Authority

Status: Accepted
Date: 2026-10-05
Decision: The wildlife ecology ships as two addons, `aee_ai` and `aee_wildlife`, and the whole layer is client-local cosmetic ecology. It reuses vanilla sound media only, and it ships in two phases.

## Context

The operator asked for a living ambient layer. In a forest the listener hears birds and insects by day, and owls and frogs by night. Near water the listener hears water. A quiet approach keeps the wildlife calling, a rush sends it quiet, and a shot sends a spook wave across the ground. Later, realistic animals appear by environment, and hunger and thirst move them between water and grazing ground.

The engine sets the bounds. The engine ambient life is per-client local. Source, BIKI Arma 3 Animals Ambient System. An agent created with `createAgent` cannot use `doMove` or `doStop`, and it can use `moveTo` and `setDestination`. Source, BIKI Animals, Override Default Animal Behaviour. An agent that is local to a dedicated server cannot `moveTo`. Source, BI feedback T155634. AEE already documents that event effects vary cosmetically per machine. Source, the README Multiplayer section.

## Decision

1. Two addons, not one. `aee_ai` owns the reusable stimulus-response substrate: the sense, decide, act, recover model, the disturbance field store and its decay, and a budgeted client tick over registered agents. `aee_wildlife` owns the ecology domain: the species mix, the sound ecology, the spawn and cull, and the needs. A future AI integration depends on the substrate alone and must not pull in fauna or sound. This is the bounded-context split.

2. The dependency edge is one way. `aee_wildlife` requires `aee_ai` and `aee_environmental`. Neither new addon is reached by `environmental`. The map is generated by `tools/architecture/addon_dependencies.py`, and `tools/tests/test_addon_dependencies.py` fails the build if `aee_ai` ever reaches into `aee_wildlife`.

3. The whole layer is client-local. The dedicated server runs no wildlife logic. The tick starts only under `hasInterface` and a valid local unit. A machine with no player computes the state and then stops before any sound or any object. This follows from BI feedback T155634: a server-side fauna driver is not supported by the engine.

4. The disturbance field is per-machine and deterministic. Each machine applies the same broadcast stimulus at the same mission time. The stimulus broadcast is rate limited to four events per second, so the network cost is bounded. Two clients at the same cell and time see the same species mix, not the same individual objects. That is acceptable for cosmetic ecology, exactly as the engine ambient system behaves.

5. The sound layer reuses vanilla media only. It never fetches, licenses or generates an audio asset. A raw vanilla `.wss` file is played with `playSound3D` and the local argument true. A vanilla `CfgSFX` class is played with the client-local `createSoundSourceLocal` as a looping positional bed. The network-global `createSoundSource` is never used, because each client owns its own bed. A context that vanilla cannot supply is a recorded finding in `docs/wiki/research/wildlife-ambience-dossier.md`, never a fetch.

6. The `playSound3D` local argument is always true. Without it the command broadcasts to every machine, which is wrong for a client-local cosmetic layer. A source contract asserts the final argument is true on every call under `addons/wildlife`.

7. The layer ships in two phases. Phase 1 is the substrate and the ambient-sound ecology. It proves the field semantics and the performance model before any animal is created. Phase 2 is the dynamic fauna, the needs and the resource travel.

8. The performance gate is separate from the core gate. The wildlife tick has its own Docker PHASE11 dry-run probe at a budget of 2 ms per call. The core `aee_core_fnc_updateEnvironment` budget stays at 5 ms and the wildlife layer never runs inside it. The dry-run probe performs no `createAgent` and no `playSound3D`, so it is safe on a dedicated server.

9. The substrate owns no user setting except its debug switch under `AEE Debug > AI`. Every ecology knob lives under `AEE Wildlife`. This keeps the reusable layer free of fauna policy.

## Consequences

- The fauna and the sound are invisible on a dedicated server with no players, by design. The server holds no anchor, so it spawns nothing and plays nothing.
- The disturbance field is not synchronised as an object. It is reconstructed from bounded events, so it can differ in detail between machines while the aggregate behaviour matches.
- A missing vanilla sound is a finding, not a blocker. The owl unit, the cow, the dolphin and the flying agents do not exist in vanilla. The owl is a sound only.
- The in-game look and the audible sound are operator-only checks. No automated test claims them.
