# The AEE dynamic variation model

A variation family declares named options. One resolver maps a selected value
combination to one concrete artifact. AEE shows the family as ONE engine entry.
The operator switches the active value in game. The mechanism is AEE's own. The
idea of one option-driven entry comes from AceArsenalExtended and is
reimplemented. AEE copies no code, config or art.

## The declaration

`data/symbology/variation_families.json` is the single declaration. The schema
is `aee.symbology.variation_families/1`. The top-level object holds:

- `schema`: the schema string.
- `retrieved`: the date the declaration was written.
- `note`: the purpose and the provenance.
- `sources`: the tables the option values derive from.
- `families`: the family list.

A family holds:

- `id`: the family name, for example `symbol`.
- `label`: the display name.
- `entry`: the one `CfgMarkers` class the picker shows, for example
  `AEE_Variation`.
- `markerClass`: the `CfgMarkerClasses` group the entry belongs to.
- `resolver`: the kernel that maps a value combination to an artifact.
- `options`: the ordered option list.

An option holds:

- `id`: the option name, for example `affiliation`.
- `label`: the display name.
- `source`: the value-set name the generator derives.
- `table`: the table the values come from.
- `grade`: `sourced`, `derived` or `UNSOURCED`, per ADR-023.

## The five option sources

The generator `tools/gen_variation_families.py` derives each option value list
from its `source`. No value is hand-listed. A new symbol in a shipped table
becomes a new option value with no edit to the declaration.

| Source | Values | Derivation | Count |
|---|---|---|---|
| `families` | affiliation | The `families` section of `symbology_tables.json`: `friend`/`b`, `hostile`/`o`, `neutral`/`n`, `unknown`/`u` | 4 |
| `dimensions` | battle dimension | `ROLES` in `tools/symbology_categories.py`: `Land`, `Air`, `Sea`, `Subsurface`, `Installation`, `Equipment`, `Other` | 7 |
| `glyphs` | function | The `glyphs` section of `symbology_tables.json`: each glyph name and its marker token | 20 |
| `echelons` | echelon | The `echelon` markers in `modifiers.json`: each `AEE_Ech_*` class and its title | 13 |
| `palette` | palette | The `symbologyPalette` choices in `initSettings.inc.sqf`: `NATO`, `OPFOR`, `Auto` | 3 |

The `dimensions` source is the marker-class role list, not the glyph
dimension field. The role list is the set of `CfgMarkerClasses` subcategories
AEE declares, so the option enumerates the frames the picker can select.

## The generated artifacts

The generator emits two artifacts:

- `addons/symbology/config_variations.hpp`: the `CfgMarkers` family entry and
  the `CfgMarkerClasses` group.
- `addons/symbology/data/variation_families.sqf`: the runtime model the kernels
  read.

Each value is emitted as `[id, label, token, grade, source]`. The generator
carries a `Generated by` header. `--check` fails when an artifact is stale.
`--table` prints the derived model.

## The resolution rule

`fnc_variationResolve` takes a family id and a state. A state is a list of
`[optionId, valueId]` pairs. The kernel fills each missing option from the
family default. For the `symbol` family it delegates to `fnc_symbolResolve`
with `sideUnknown` and the mapped affiliation, dimension, function, echelon and
palette. It returns `[affiliation, markerType, markerColourClass, echelon]`.
`fnc_symbolResolve` stays the single source of truth for the symbol. The
variation layer only selects the inputs.
